## Keputusan boundary final

| Repository | Ownership final |
|---|---|
| `alos-contracts` | Bahasa bersama: JSON Schema, OpenAPI, event, contoh, compatibility, dan generated type resmi. |
| `alos-backend` | Authority platform: identity, authorization, tenant/scope, canonical state, ToolExecutor, audit, decision, release, persistence, dan business domain. |
| `genesis-ai` | AI Control Plane: capability intelligence, generic agent runtime, orchestration, research/review intelligence, evaluasi, dan ModelGateway. |
| `alos-web` | Human/product experience. Hanya berkomunikasi dengan Backend dan tidak menentukan authority. |
| `alos-infra` | Runtime/deployment infrastructure: Compose, networking, reverse proxy, PostgreSQL service, observability boundary, backup, restore, dan runbook. |

Arah komunikasi yang dipertahankan adalah `Web -> Backend -> GENESIS`. Tindakan agent selalu `GENESIS -> ToolRequest -> Backend ToolExecutor -> ToolResult`. Aplikasi tidak boleh memiliki salinan permanen contract lintas service.

## Arti klasifikasi dan urutan

| Klasifikasi | Arti |
|---|---|
| `REUSE` | Dapat dipindahkan dengan perubahan mekanis kecil; behavior dan ownership sudah sesuai. |
| `ADAPT` | Behavior berguna, tetapi interface, dependency, configuration, atau framework boundary harus disesuaikan. |
| `SPLIT` | Satu modul legacy memuat lebih dari satu ownership final dan harus dipecah berdasarkan boundary. |
| `DEPRECATE` | Dipertahankan sementara sebagai referensi/transisi, lalu dihentikan setelah pengganti tervalidasi. |
| `DO_NOT_MIGRATE` | Tidak dibawa ke target karena kosong, berbahaya, duplikatif, atau bertentangan dengan architecture freeze. |

Kolom `Migration Order` menggunakan fase berikut:

1. Contract dan compatibility baseline.
2. Backend authority foundation serta PostgreSQL runtime lokal.
3. Canonical domain, persistence, audit, dan ToolExecutor Backend.
4. GENESIS AI/runtime melalui internal contracts.
5. Web melalui public Backend API.
6. Deployment, worker, observability, dan cutover operasional.
7. Penghapusan compatibility shim dan pengarsipan legacy.

## Modul berisiko tinggi

1. **`runtime/service.py`** — satu execution path mencampur orchestration, provider usage, ToolExecutor, evidence, budget, dan direct database persistence. Pemisahan salah dapat menciptakan dual authority atau melewati ToolExecutor.
2. **`genesis/`** — chat dan semantic analysis mencampur reasoning AI dengan business persistence, router database, upload, dan operational access. Ini adalah titik utama pemisahan Backend/GENESIS.
3. **`tools/`** — registry/executor legacy bergantung pada domain dan database. Tool request client boleh ada di GENESIS, tetapi policy, permission, allowlist, execution, dan audit wajib tetap di Backend.
4. **`agents/` dan `capabilities/`** — draft/definition intelligence bercampur dengan registry dan lifecycle authoritative. Cutover harus mencegah GENESIS menulis registry secara langsung.
5. **24 migration SQL di `infra/database/`** — schema ownership tersebar dan berada di repository yang salah menurut boundary final. Migrasi harus menjaga data, foreign key/reference, dan urutan append-only tanpa membuat dua writer.
6. **Identity, authorization, permissions, dan security** — perubahan identifier atau default policy dapat membuka akses lintas tenant. Semua target harus deny-by-default.
7. **Release/governance** — istilah AI review, validation, approval, dan release berdekatan di legacy. Contract serta test harus membuktikan bahwa AI tidak memberi final approval/release.
8. **Documents/sources/evidence** — canonical metadata, object access, analysis AI, dan evidence lineage saling terkait. Data access harus selalu berupa authorized context/reference.
9. **Frontend governance/Genesis modules** — local DTO dan action helper berpotensi menjadi salinan contract atau menghitung authority di browser.

## Urutan migrasi yang direkomendasikan

1. **Kunci source dan buat behavior baseline.** Gunakan pinned SHA dokumen ini, ekspor daftar test, endpoint, tabel, dan configuration tanpa mengubah sumber.
2. **Stabilkan `alos-contracts`.** Petakan Agent, Capability, ExecutionContext/Budget, Tool, Evidence, Research, Review, Decision, Release, event, error, dan canonical ID. Tambahkan compatibility fixtures dari payload legacy yang sah.
3. **Siapkan authority foundation Backend.** Migrasikan identity/authentication/authorization/permission/security lebih dulu, lalu audit dan persistence ownership. Jalankan PostgreSQL dari infra, tetapi application migration tetap dimiliki Backend/GENESIS.
4. **Migrasikan Backend canonical domains.** ToolExecutor, agent/capability registry, documents/sources/evidence, governance/decision/release, operational domains, dan jobs. Buat data migration append-only dan satu writer per entity.
5. **Migrasikan GENESIS di belakang internal contracts.** ModelGateway dan provider adapters, generic agent runtime, capability/agent draft intelligence, orchestration, research/review/evals. GENESIS tidak menerima DB connection ke business schema.
6. **Buktikan integration boundary.** Uji `Backend -> GENESIS` dengan correlation ID serta `GENESIS -> ToolRequest -> Backend ToolExecutor -> ToolResult`; negative tests wajib mencakup permission, scope, tenant, allowlist, timeout, dan invalid response.
7. **Migrasikan Web per experience.** Gunakan generated types/public API. Mulai shell dan read-only projection, lalu command governance; jangan pernah mengkonfigurasi URL GENESIS pada browser.
8. **Cutover infra dan operasi.** Validasi Compose, Caddy, private networks, health, worker, observability, backup/restore, dan rollback. Lakukan staging rehearsal sebelum production.
9. **Deprecate monolith secara terukur.** Setelah parity test, data reconciliation, audit lineage, dan rollback tervalidasi, hentikan route/job legacy satu per satu; arsipkan dokumen dan script transisi.

## Technical debt yang diketahui

- Beberapa file menjadi pusat tanggung jawab terlalu besar: `runtime/service.py` sekitar 1.467 baris, `agents/registry.py` sekitar 860 baris, `documents/center.py` sekitar 873 baris, `genesis/chat.py` sekitar 718 baris, dan `tools/executor.py` sekitar 522 baris.
- Domain/service code melakukan query `psycopg` secara langsung sehingga transaction, policy, dan ownership sulit dipisahkan.
- Pydantic/local TypeScript DTO tersebar di service dan Web; berisiko menduplikasi canonical contract.
- Agent/capability intelligence dan authoritative registry berada dalam modul yang sama.
- Router/semantic analysis GENESIS membaca atau menulis database platform secara langsung.
- ToolExecutor legacy mengetahui banyak business adapter/domain, sehingga allowlist dan execution core belum cukup terisolasi.
- Application migrations berada di `infra/database`, sementara ownership tabel mencakup Backend dan AI runtime.
- Belum ada modul mandiri untuk skills, memory, evals, atau research; behavior terkait tersebar dan coverage taxonomy belum seragam.
- Provider smoke/config legacy berdekatan dengan runtime; credential dan direct provider imports perlu dikunci di adapter ModelGateway.
- Banyak integration test bergantung pada PostgreSQL dan environment; pemisahan unit/contract/integration belum konsisten.
- Folder `data/` dan `tools/` berisi placeholder kosong, bukan reusable implementation.
- Script reset bersifat destructive dan belum layak menjadi baseline operasional lintas environment.
- Dokumen implementation/report lama dapat bertentangan dengan Architecture Freeze multi-repository bila tidak diberi label historical.
- Frontend memiliki feature client dan type lokal yang perlu diganti dengan generated contracts secara bertahap.
- Object storage, observability, dan production backup masih berupa integration/config boundary; provider dan SLA operasional belum diputuskan.

## Kriteria keluar tahap inventory

Tahap ini selesai ketika seluruh path di atas memiliki owner target, contract dependency, risiko, dan urutan yang jelas. Tahap ini tidak mengotorisasi copy source, perubahan schema production, data migration, deployment, atau penghentian monolith. Setiap penyimpangan besar dari boundary final wajib melalui ADR sebelum implementasi migrasi dimulai.
